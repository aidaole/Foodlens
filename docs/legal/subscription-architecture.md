# FoodLens 订阅与登录方案

截至2026年10月16日，0.4.4 已接入 RevenueCat 原生 SDK 和月会员页面，准备购买、恢复、管理流程，并实现签名匿名身份及服务端额度校验。用户选择人民币 9.90 元/月、免费累计三次、会员每个订阅周期五十次。真实购买开关保持关闭，商店及 RevenueCat 的配置和实际购买测试尚未完成。RevenueCat 是独立的订阅服务，有适用于 Expo 的 SDK，不是 Expo 自动附带的收费功能。

## 是否必须登录

只做单一商店内的订阅，可以不让用户注册 FoodLens 账号。RevenueCat 可生成匿名 app user ID；用户通过自己的 Apple/Google 商店账号确认购买，应用提供恢复购买入口。同平台重装或换机应使用相同商店账号恢复，并测试 RevenueCat 项目的恢复/转移设置。匿名 ID 本身不支持 Android 和 iOS 之间共享会员，也不提供历史记录同步。依据：[RevenueCat 用户标识](https://www.revenuecat.com/docs/customers/identifying-customers)。

如果要跨平台会员、同步历史或让用户找回 FoodLens 身份，应接入身份服务并使用稳定的服务端用户 ID。可以用托管身份服务，避免自己保管密码；仍要接入登录界面、会话验证、退出与删除账号流程。登录不会自动同步历史，云端历史库和相应隐私披露是另外的开发工作。

## 各组件负责什么

| 组件 | 负责 | 仍需我们做 |
| --- | --- | --- |
| Expo / React Native | 应用、原生构建与分发工具 | 页面、数据流程、权限与业务逻辑 |
| Apple / Google 商店 | 付款确认、扣款和商店订阅管理 | 开发者协议、税务/收款、商品、销售地区与价格配置 |
| RevenueCat | 包装商店购买 API，校验与追踪购买、返回会员权益；可使用预制付费墙 | SDK接入、商品与权益映射、购买/恢复/管理入口、错误状态、权益使用和后台联动 |
| 身份服务（如后续选择 Firebase Auth） | 身份验证与登录会话 | 登录体验、用户 ID 映射、删除账号、后端验证 |
| Cloudflare 后端 | 食品识别与额度控制 | 验证调用者、核实有效会员、按套餐计费周期限额，处理退款/到期与防滥用 |

RevenueCat SDK 的 `logIn(appUserID)` 是关联购买身份，不是验证邮箱或密码。不能让客户端传一个会员 ID，就当作已经验证此用户。RevenueCat 当前还提供 Authentication 私测文档，但它仍依赖外部身份提供商；文档列出的 Android/混合 SDK 支持尚未开放，因此不作为本 Expo 双平台方案的现成登录系统。依据：[RevenueCat Authentication](https://www.revenuecat.com/docs/customers/customer-authentication)。

## 适合 FoodLens 的下一阶段

建议保持免费拍照入口简单，不在首次启动强制注册。需要订阅时再展示明确的会员权益。跨平台身份可先接托管的匿名身份，为后端提供可验证的会话；用户需要跨设备找回或跨平台通用会员时，再绑定邮箱或其他正式登录身份。这一方案需要验证“匿名身份—商店交易—会员权益”的绑定与恢复流程，不能把客户端上报的 ID 当作证明。

如果选择完全无登录首发，也必须为收费的云端接口建立可验证的付费身份绑定和服务端额度校验；RevenueCat 的匿名 ID 和公开 SDK key 不足以保护后端。可以选择在订阅前做轻量登录来简化安全绑定。具体选择应在确认是否需要跨 iOS/Android 会员后落实。

当前匿名凭证由后端签发，客户端不能指定会员身份；会员按服务端 RevenueCat 查询和商店交易计数，恢复或转移身份不赠送同一期新额度。后续配置月订阅商品、RevenueCat 和正式协议，验证购买及恢复流程，再开放真实购买。无需自行开发信用卡扣款系统。
